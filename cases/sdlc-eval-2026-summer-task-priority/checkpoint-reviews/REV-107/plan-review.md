# Проверка PLAN-REVIEW: REV-107

## Решение

Граница не принята как каноническая. Само ревью завершило одну полноценную
волну из четырёх независимых групп и внесло полезные коррекции, но пропустило
материальную связь с долговечным сценарием.

## Что сработало

- Все четыре reviewer Work завершились в одной волне после one-shot capacity
  probe; оркестратор не прерывал молчащие сессии.
- Найдены и исправлены два действительных риска: доказательство backfill для
  уже существующей задачи и единый flow-scoped мир для browser/API проверки.
- Ревизия плана выросла с 1 до 2, а `code-work-batch.json` детерминированно
  пересобран. Aggregate gates остались в CODE fan-in, а не на P2.

## Причина непринятия

`PRT-007` явно связан с `.memory-bank/scenarios/SCN-002-workspace-task-core.md`.
Новый контракт меняет поведение и доказательство task flow, однако итоговый
`plan.json` не содержит ни одного `document_updates` для сценария и ни одного
решения, объясняющего его неизменность. Следовательно, ни один CODE Work не
обязан актуализировать долговечный acceptance contract. `pnpm docs:check` не
может заменить эту семантическую проверку.

## Исправление следующей пары

PLAN и PLAN-REVIEW теперь обязаны для каждого связанного сценария назначить
одного владельца обновления или явно записать обоснование отсутствия влияния.
REV-107 сохранён как диагностическое доказательство и не используется как
вход или стартовый checkpoint.
