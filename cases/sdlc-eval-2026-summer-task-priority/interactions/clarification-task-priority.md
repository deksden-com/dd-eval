Используем четыре уровня: `no_priority`, `low`, `medium`, `high`; для новых и существующих задач по умолчанию — `no_priority`. Приоритет может менять участник workspace, в том числе для архивной задачи. В списке задач показываем понятное текстовое значение и не меняем существующий порядок задач только из-за отсутствующего приоритета.

Приоритет обрабатывается у задач независимо от текущего статуса проекта: задачи
архивных проектов сохраняют и показывают своё значение. Из общего read-only
правила архивного проекта делаем узкое исключение: участник workspace может
изменить только приоритет задачи; смешанное изменение приоритета и других полей
отклоняется целиком.
