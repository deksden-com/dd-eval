# Единый пакет уточнений

Этот пакет передаётся каждому агенту целиком после того, как он закончил задавать вопросы на `specify`. Пакет одинаков для всех прогонов независимо от качества и количества вопросов.

- Допустимые значения: `none`, `low`, `medium`, `high`, `urgent`.
- Новый атрибут обязателен в базе данных; для существующих и новых задач значение по умолчанию — `none`.
- Создание задачи принимает необязательный `priority`; отсутствие означает `none`.
- Обновление задачи принимает необязательный `priority`; отсутствие сохраняет текущее значение. Явное неизвестное значение возвращает существующий публичный `400 VALIDATION_ERROR` без изменения задачи.
- Все API-представления задачи возвращают `priority`.
- Приоритет не меняет существующий порядок задач. Сортировка и фильтрация по приоритету не входят в задачу.
- В форме создания и на странице задачи используется обычный подписанный `select`. Начальное значение формы создания — `none`.
- В списке задач показывается текстовая метка приоритета. Цвет может быть дополнительным сигналом, но не единственным.
- Оба workspace-ролевых уровня, которые уже могут изменять задачи, могут изменять и приоритет. Новых owner-only правил нет.
- Архивный проект остаётся полностью read-only, включая приоритет.
- Workspace isolation, `404` для недоступного workspace и существующие session/auth правила не меняются.
- Детерминированная фикстура `task-alpha-one` получает `high`, `task-beta-one` — `none`.
- Нужна forward-only миграция. Новая зависимость, background job и отдельная settings-система не нужны.
