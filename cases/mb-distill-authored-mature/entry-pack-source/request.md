# Дистилляция опыта ledger-проекта

Изучи фактический опыт этого проекта через mb-distill, а не через аудит или
исправление проекта. Нужны переносимые практики, их применимость, отличие от
замороженного канона и ограничения, подтверждённые исходниками и использованием.
Не считай утверждение в документации доказательством реализации.

Границы исследования: domain-04 (scenarios/evidence) и process-09
(evidence/acceptance/closure). Сохрани обе линзы отдельно; остальные аспекты
явно отметь вне согласованного scope, не выдавая их за исследованные.
Достаточно не более одной содержательной практики на каждый выбранный аспект.
Каждую практику должны независимо проверить обе предусмотренные критические
роли. Не превращай замечания к исходному MB в новый repair/SDLC RUN.

Назначение согласовано: существующий каталог `../distill-destination`
относительно исходного project_root (не относительно snapshot cwd или RUN Home).
Он подготовлен как отдельная тестовая база знаний. Единственный разрешённый
документ — `.memory-bank/mbb/distilled-practices.md` в этом назначении.
После независимого review разрешаю перенести туда выбранные adopt/adapt
практики через штатную ограниченную публикацию. Не меняй другие документы.
Сохрани исходный смысл, идентификатор и ограничения уже существующего документа.

Если канон уже содержит практику, честно оставь duplicate/observe либо предложи
адаптированный пример с явно показанной дополнительной ценностью, а не новое
обязательное правило ради публикации. Не требуется фиксированное число принятых
кандидатов; отсутствие полезной новизны лучше выдуманной практики. Проектный факт
или его ограничение не становится общей гарантией для других проектов.

Исходный проект, его Memory Bank, DEF, Git index, режимы файлов и ссылки должны
остаться неизменными. Не запускай проверки проекта, установки, миграции, release
или deploy: можно изучать код проверок, но не заявлять их выполнение. Внешнее
исследование нужно только если оно способно изменить оценку; его использование
и отсутствие явно укажи. Независимо проверь фактически опубликованный результат
и сохранение прежнего содержания; заверши тот же RUN с источниками, критикой,
непринятыми кандидатами и ограничениями. Пиши содержательные выводы по-русски.
