# Повторная проверка исполнения плана 023

Дата: 2026-09-05. Это сверка реализации, не приёмка E2E.
Разделы до «Завершение пакета beta.15» сохраняют историческое состояние beta.14;
актуальный итог находится в последнем разделе.

Предыдущий отчёт о полном завершении был неверен: версия beta.13 закрывала
только часть плана. Проверка выполнена по исходному коду, опубликованному npm
архиву и тестам, а не по формулировке предыдущего отчёта.

## Исправлено при повторной проверке

1. `operation_observation_lost` отсутствовал в классификаторе журнала, хотя
   раннер уже обрабатывал его как неизвестный исход. Теперь общий классификатор
   применяется в обоих местах; разрыв соединения также не завершает операцию.
   `details`, `retryable` и ограниченная цепочка `cause` сохраняются при переносе
   ошибки. Добавлены проверки позднего результата и запрета повторной отправки.
2. Блокировка журнала отбиралась у живого процесса по возрасту. Теперь у неё
   уникальный файл владельца; возраст не даёт права удаления. Удаляется только
   файл подтверждённо умершего владельца. Неизвестное владение блокирует запись
   с объяснением. `finally` не удаляет чужую новую блокировку.
3. ACP после паузы удалял ожидающий запрос. Теперь сохраняет тот же запрос,
   записывает `observation_gap` и даёт ограниченное новое окно наблюдения, не
   изменяя timestamp активности модели. Поздний нативный ответ принимается.
   Grok также использует скользящее окно ACP вместо абсолютного лимита prompt.
   AGY различает подтверждённую неактивность и недоступность наблюдения.
4. Пять daemon dispatch-путей сохраняют requested/hash и терминальный результат
   до ответа по сокету. Повтор того же id не повторяет действие, другие параметры
   отклоняются. `daemon operation --operation-id` читает результат. Это ещё не
   означает, что все ветки автоматического восстановления раннера используют
   эти новые receipts — см. остаток ниже.
5. Grok мог не отменить активный root без детей. Codex/OpenCode проверяли дерево
   сразу после acknowledgement отмены. Общий ограниченный цикл наблюдения ждёт
   подтверждения и не сообщает clean при незавершённом запросе. Codex учитывает
   зарегистрированные prompt/start-сессии и обнаруженных потомков. Grok inspect
   больше не выполняет session/load и не переключает активную сессию.
6. Учёт процессов различает owner PID/start identity и PID дочернего процесса.
   Живой владелец не теряет аренду после сна; живой сиротский процесс можно
   согласованно прибрать после смерти известного владельца. Проверки не
   освобождают порты, пока принадлежащее им дерево живо.
7. Ошибка spawn/регистрации проверки больше не вызывает необработанное событие
   error и не возвращает результат раньше закрытия shell. Потеря аренды
   останавливает цикл продления и запускает одну эскалацию.
8. Work prompt перечисляет реальные obligation refs и реальные finding refs;
   обычному Work не подставляется фиктивный FIND. Посторонние resolutions
   отклоняются. Удалены вымышленные пути receipts в примерах ревью. Ясно
   разделены work finish и проверки остальных run_at-гейтов.
9. CODE/MERGE используют общий managed bootstrap: одинаковая среда, полные
   логи, completion marker, progress и повторная проверка существующего процесса.
   Небезопасный cache по одному имени каталога удалён: подготовка пока выполняется
   при входе в CODE. Кэш с объявленными dependency inputs ещё не реализован.
   Проектный bootstrap dd-tasks проверяет запуск Vitest и реальную сборку Rollup;
   имена этих пакетов не встроены в движок.
10. npm beta.13 содержал `built_with_canon` с null во всех полях. Новый
    prepublishOnly проверяет наличие канонической версии/коммита и совпадение
    сборки с исходным коммитом. Для beta.14 обязателен readback самого npm-архива.
11. Канон 4.0.3 продолжал объявлять memory_bank_version=4.0.2 и допускал движок
    beta.4, который не понимает result@3. Исправлено в 4.0.4: минимум beta.13,
    рекомендация beta.14. В dd-tasks перенесён весь канонический flow delta с
    4.0.2: две схемы и compatibility, с сохранением проектных настроек.

## Остаток на момент beta.14 — исторический снимок

- P1: общий модуль наблюдаемого времени для Codex/OpenCode и всех управляющих
  вызовов; системное предотвращение обычного сна на время локального запуска.
  Внутренний timeout закрытого ZCode остаётся отдельным риском провайдера.
- P2: связать верхний operation_id раннера и каждый запрос демона во всех
  normal/resume/reference/Judge/HITL путях; автоматически потреблять сохранённый
  поздний результат до любого следующего prompt. Сейчас доступны durable
  receipts и их инспекция, но это не полная автоматическая приёмка recovery.
- P3/P4: завершить ревизию подавленных ошибок startup/shutdown, периодического
  heartbeat демонов и реакции на false heartbeat. Проверить каждый адаптер на
  игнорирующем SIGTERM provider, PID reuse и умершем лидере с живой группой.
  Неопределённую принадлежность группы сейчас безопаснее оставить ошибкой,
  чем завершать чужой процесс. Это не равнозначно автоматической уборке.
- P6: если нужен cache готовности — добавить явно объявленные проектом inputs
  и identity среды. Не возвращать прежний некорректный cache. Причина конкретной
  старой неполной установки Rollup не доказана повторным успешным запуском.
- P7: нет полного runtime start/stop для интерактивных сервисов агента с
  выделением портов, readiness и связанными сценарными receipts.
- P8: нет полного представления observation gaps/подтверждённого сна в итоговом
  отчёте и автоматической финализации всех поздних usage snapshots.
- Приёмка: настоящие provider-smoke для всех изменённых путей и новый input
  checkpoint/пара для будущего эвала ещё не приняты. Старые прогоны не менялись.

## Завершение пакета beta.15

### Что добавлено и проверено

1. Общий ObservationClock считает наблюдаемое время и сохраняет разрыв часов
   отдельно от прогресса. Codex принимает активность дочерних событий; OpenCode
   проверяет изменение нативных сообщений дерева. AGY использует общий таймер
   управляющего соединения. Grok/ZCode сохраняют исходный ACP запрос после gap.
   Для продуктивных вызовов раннер включает временный parent-bound inhibitor
   обычного сна (macOS/Linux), с журналом его доступности и освобождением.
2. Общий callDriver сохраняет связь с родительской операцией раннера. Перед
   следующим продуктивным вызовом импортирует поздний durable result. После
   crash неизвестный исход блокирует новую отправку; recovery не пересылает
   prompt. Reference cleanup сохраняет прежний каталог вместо удаления.
   requested.json публикуется атомарно и эксклюзивно: тест 30 конкурирующих
   запросов подтверждает единственное выполнение, без частичного JSON.
3. У всех пяти адаптеров startup cleanup сохраняет первоначальную ошибку и
   ошибки очистки. Heartbeat периодический; false запрещает новые productive
   операции. Stop не объявляется успешным при живом дереве. CLI проверяет
   PID/start identity непосредственно перед сигналом; неизвестную группу не
   убивает. Повторный finish с тем же исходом идемпотентен.
4. CODE/MERGE используют общий managed bootstrap без небезопасного readiness
   cache. Это намеренное упрощение P6: проектный bootstrap вызывается вновь,
   а менеджер пакетов сохраняет собственный cache. Движок не угадывает список
   dependency inputs и не пропускает проверку среды по прошлому успеху.
5. Добавлен runtime process start/stop для интерактивных HTTP-сервисов:
   реестр, уникальные порты, lease, readiness, логи/receipt в RUN. Два настоящих
   локальных сервиса проверены одновременно: остановка одного не затронула
   второй. Work получает инструкции и точную команду остановки. Readiness
   не выдаётся за доказательство сценария.
6. Итоговые candidate/evidence содержат observation gaps и отдельную оговорку
   о времени; неизвестный OS sleep остаётся null. В recovery импорт результатов
   предшествует сбору usage; используется существующий пересчёт нативной
   накопительной статистики, а не сумма повторных snapshots.
7. Живой smoke выявил дополнительный дефект Grok: list_running не содержит
   завершённых детей, а observer игнорировал native tool results. Добавлен
   разбор только подтверждённых spawn_subagent/TaskOutput, без чтения prose
   модели. Исправлено также перекрытие нового completed старым running.
   У Codex capacity теперь читает task_complete самого ребёнка, а не только
   устаревший SubAgentActivity родителя. Обе ошибки покрыты регрессиями.
