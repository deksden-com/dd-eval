# SPC-010 — агентный выбор проверок и безопасный HITL

## Цель

Сохранить смысловые решения за планирующим агентом, а за `dd-flow` — только
детерминированную проверку структуры, порядка и защищённых операций. Убрать
два источника ложных дефектов: испорченный ответ пользователя из heredoc и
подмену результатов ревью маршрутизирующей картой аспектов.

## Контракты

1. `protocol-plan@4` содержит единый `checks[]` каталог. В `items` и
   `acceptance` остаются только `check_refs`.
2. Проверка имеет `id`, `command`, `purpose`, `run_at`, `availability`.
   `planned` называет Work-поставщик; новый `@check/...` дополнительно хранит
   точное `definition`. Потребитель зависит от поставщика.
3. Профиль проекта предоставляет алиасы, сводные гейты и список защищённых
   команд. Он не является закрытым списком обычных локальных проверок.
4. Планировщик выбирает проверки и при необходимости планирует Work,
   материализующий новую проверку. CLI валидирует ссылки, граф, гейты и
   защищённые команды, но не оценивает релевантность или «тяжесть» проверки.
5. `aspect-map@3` — только манифест применимости и маршрутизации. Состояние
   ревью и находки живут в дочерних Work и `decision.json`.
6. Ёмкость субагентов — единая переменная RUN
   `runtime.subagent.available_slots`; одна проба запускает ровно 15 задач
   одновременно, без повторов и Work-регистрации.
7. Если ответ HITL меняет формулировку обязательства, PROTOCOLIZE добавляет
   `obligation_amendments` с `target_id`, заменой, причиной и `HITL-*`.
   SPECIFY остаётся неизменяемым; PLAN использует эффективные обязательства.
8. Хук никогда не меняет команды с heredoc. Стартовые команды переписываются
   только когда это один однозначный lifecycle-вызов. Resume с stdin
   сопоставляется по неизменяемым аргументам и событию хука.

## Приёмка

- тест подтверждает, что heredoc не меняет ни одного байта ответа;
- план с прямой локальной проверкой и плановой новой проверкой валидируются;
- план без последней проверки или без зависимости поставщика отклоняется;
- запуск PLAN-REVIEW не меняет `aspect-map.json`;
- протоколизатор сохраняет и использует допустимую HITL-поправку;
- целевой тест, typecheck, lint и build пары проходят до нового канонического
  прогона.
